# 공략 방법론 (일반 원칙)

외부 라이트업이 아니라 표준 침투테스트 순서다. LLM 컨텍스트로 제공된다.

- **열거를 먼저 끝낸다.** 포트 하나에서 막혀도 다른 표면을 먼저 다 본다
  (depth-first trap 회피). 모든 열린 포트의 서비스·버전·기본 자격증명을 수집.
- **자격증명은 전부 재사용한다.** 한 서비스에서 얻은 사용자/암호/해시는 SMB·
  WinRM·SSH·DB·웹 로그인에 교차 시도(패스워드 재사용이 흔함).
- **privesc 순서**: 설정오류(sudo -l → SUID/capabilities → cron/서비스 → 쓰기가능
  파일 → 저장된 자격증명)를 먼저, 커널/서비스 익스플로잇은 최후. 비가역·불안정한
  수단은 다른 경로 소진 후.
- **증거로 판정한다.** 도구의 "success" 출력을 믿지 말고 독립 확인(셸은 토큰 왕복,
  파일읽기는 아는 내용 대조). 플래그는 '어떻게 얻었는지'(선행 익스플로잇)까지 기록.
- **막히면 가설을 바꾼다.** 같은 표면에 반증이 쌓이면 점수를 내리고 다른 표면으로.
  전제조건 미충족(도구 없음·리스너 오류)은 '반증'이 아니라 '준비 과제'다.
