# Writeup 미참조 — 조치와 증빙

대회 규칙: *"가능한 한 Writeup 을 참고하지 않도록 조치"* + *"1등 발표 시 어떤
조치를 취했는지 설명 포함"*. 따라서 **설명 가능하고 검증 가능한 형태**로
만들어야 한다. 원칙 선언문은 증빙이 아니다.

## 무엇을 막는가 — 경계부터

| 구분 | 예 | 판정 |
|---|---|---|
| 범용 기법 문서 | HackTricks, 도구 man, CVE 설명, 프로토콜 문서 | **허용** |
| 그 머신의 풀이 | 머신명 Writeup/walkthrough, 포럼 힌트, 플래그 값 | **차단** |
| 경계 사례 | 머신에 쓰인 CVE 의 공개 PoC | 허용(범용) — 단 질의에 머신명 금지 |

구분 기준은 "대상에 특정되었는가"다. 기법은 지식이고, 그 머신의 정답은 답안이다.

## 조치 (설계 — 구현 미완)

### A1. 지식원 allowlist
L5 는 **로컬 미러만** 참조한다. 미러는 범용 기법 문서로 한정하고, 머신명 색인을
포함하지 않는다. 런타임에 새 지식원을 추가할 수 없다.

### A2. 에이전트 셸의 외부 송신 차단
`ShellSession` 이 실행하는 명령은 HTB 대상·VPN 대역 외로 나가지 않아야 한다.
`scope_guard` 가 이미 대상 범위를 강제하므로 egress 화이트리스트를 같은 지점에
얹는다. 검색엔진·포럼·깃허브 접근 자체가 불가능해진다.

### A3. 질의 필터
L5 검색 질의에서 머신명·대상 IP·`writeup`·`walkthrough`·`solution` 토큰을
거부한다. 우회 시도도 로그에 남는다.

### A4. 전 질의 감사
질의·반환 절·시각을 `audit_*.jsonl` 에 남긴다. 발표 때 **"이 런에서 참조한
지식은 전부 이 로그"** 라고 제시할 수 있어야 한다. 사후에 로그만 보고 재현 가능할 것.

### A5. 사람 입력 경로 차단
무개입 자동화가 목표이므로 런 중 사람이 힌트를 넣을 통로가 없다. 입력은
VPN 프로필과 대상 IP뿐. 이것 자체가 가장 강한 조치다 — **개입 횟수 0 을
로그로 보일 수 있으면 설명이 끝난다.**

## 통제할 수 없는 것 — 정직하게 명시

**모델의 사전학습 지식은 막을 수 없다.** 공개된 지 오래된 HTB 머신은 풀이가
학습 데이터에 포함돼 있을 가능성이 있고, 우리가 검색을 전부 끊어도 모델이
이미 알고 있을 수 있다. 이건 조치로 해결되지 않으며, 해결됐다고 말해서도 안 된다.

완화책은 **측정 설계**다:

- **히든문제(10-21 공개)가 유일하게 깨끗한 측정치다.** 공개 시점이 늦을수록
  학습 데이터 오염 가능성이 낮다. 자체 평가의 주된 근거를 여기에 둔다.
- 기존 Active Machine 측정치는 오염 가능성을 **명시한 상태로** 보고한다.
- 오염 탐지용 대조: 같은 머신에 대해 (a) 검색 전면 차단 (b) L5 허용 두 조건의
  경과시간을 비교한다. (a)가 비정상적으로 빠르면 사전지식 의심 신호다.

발표에서는 이 한계를 먼저 말하는 편이 낫다. 숨기면 질문 한 번에 무너진다.
